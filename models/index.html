    Choosing a checkpoint

    For modification identities, choose a supervised classifier or a prototype model that includes your target classes. Supervised models use classifiers trained on labelled data. Prototype models learn prototypes from small labelled datasets and use footprinting to account for neighboring effects. Both use contextual PoreFM representations. The released prototype models cover more modification types, so a modification can have a prototype model even when no supervised model is available.

    • backbone.pt contains the pretrained backbone for embeddings, pairwise comparison, and downstream tasks.
    • pretraining.pt contains the same backbone plus pretraining objective heads and the EMA target encoder. Optimizer and scheduler states are excluded.
    • Zero-shot and prototype bundles contain their required backbone and fitted components; separate model-component paths are unnecessary.
    • Supervised model.pt files contain the backbone, classifier, preprocessing, class labels, and base/modification-code defaults.

    Derived models use the corresponding RNA or DNA pretrained backbone and include the weights needed for inference. A separate base-model download is unnecessary when using a derived model.

    Downloading and using models

    Use --model OWNER/REPOSITORY@vVERSION to download a published release automatically. The version is part of the same argument; there is no separate version option. An explicit tag such as @v0.1.0 is required.

    porefm prototype classify \
  --model WGLab/PoreFM-RNA_prototype@v0.1.0 \
  --bam_path basecalls.bam --pod5 pod5/ --ref reference.fa \
  --chrom chr1 --motif 'N 0' \
  --effect_penalty 50 \
  --output_dir outputs/prototype

    The four inference commands select the appropriate artifact from the release:

    Command Example model argument Artifact selected
    detect-modification --model WGLab/PoreFM-RNA_m6A-Inosine@v0.1.0 Complete supervised classifier.
    zero-shot detect --model WGLab/PoreFM-RNA_zero-shot@v0.1.0 Complete canonical-null bundle.
    prototype classify --model WGLab/PoreFM-RNA_prototype@v0.1.0 Complete prototype bundle.
    pairwise-comparison --model WGLab/PoreFM-RNA@v0.1.0 Pretrained backbone; supervised classifier releases can also supply embeddings and class filtering.

    For supervised pseudouridine detection, use --model WGLab/PoreFM-RNA_pseU@v0.1.0 with --read_based --motif 'T 0'. Its class labels are U and pseU; RNA uridine is represented as T in BAM sequences and modification tags. The checkpoint supplies SAM modification code 17802. The HeLa example runs both RNA supervised models.

    Downloads use public HTTPS file URLs with Python's standard library. No Hugging Face package, CLI, account, or login is required for these public releases. PoreFM reads manifest.json, pins the checkpoint download to the resolved repository commit, and verifies its size and SHA-256 before use. It never silently substitutes the latest release for a missing version.

    Cache directory

    The default cache is ~/.cache/porefm/models, or $XDG_CACHE_HOME/porefm/models when XDG_CACHE_HOME is set. Configure a shared cache through the environment:

    export POREFM_MODEL_CACHE=/path/to/shared/porefm-models

    Alternatively, add --model-cache-dir /path/to/cache to an inference or download command. This option takes precedence over the environment variable. PoreFM verifies cached checkpoint checksums and reuses valid files without contacting the server. Concurrent processes sharing a cache coordinate downloads. The cache is independent of Hugging Face's SDK cache.

    Prefetching and offline use

    Download on a machine with internet access before launching a GPU job:

    porefm models download \
  --model WGLab/PoreFM-RNA_prototype@v0.1.0 \
  --model-cache-dir /path/to/shared/porefm-models

    The command prints the verified local checkpoint path to stdout; download progress goes to stderr. On the compute node, use the same --model and cache directory, adding --offline to prohibit network access. A missing or corrupt cached model then produces an error.

    Base-model repositories default to backbone.pt. Request the pretraining checkpoint explicitly when needed:

    porefm models download --model WGLab/PoreFM-DNA@v0.1.0 --file pretraining.pt

    Local files and reproducibility

    Load local checkpoints with --model-path or --model_path. Use either a local path or --model, not both. Local paths never trigger a download, and can point to files obtained manually or through another cache. For training, pass the prefetched checkpoint path to the training command's checkpoint-loading option.

    For --model runs, run_manifest.json records the requested model reference, version, resolved repository commit, selected filename, checkpoint SHA-256, and release-manifest SHA-256 under model_source. The local checkpoint path is also recorded. This provenance is retained when using cached models offline.

    For setup and examples, see inputs and models, supervised detection, zero-shot detection, pairwise comparison, and prototype-based joint footprinting.

    Checkpoint checksums

    These SHA-256 checksums identify the exact checkpoint files for version 0.1.0. Each Hugging Face repository also includes SHA256SUMS and manifest.json. After downloading the checkpoints listed in that repository's SHA256SUMS, run this command from their download directory:

    sha256sum -c SHA256SUMS
